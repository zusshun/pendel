# Change: Ondo 实盘做市机器人（首版，单市场小金额）

## Why

回测结论（`docs/reports/2026-11-04-final-conclusion.md`）表明，RDDT 和 IBM 在周末竞争很低、安全边际大，但需要 44 小时持续挂单，并随价格移动调整报价。用户没有时间盯盘，所以需要一个可以无人值守运行、能自动执行上线判据、出问题时能自动停下来的机器人。

## What Changes

- 新增 `pendle maker` 常驻服务，只操作 Ondo Perps 账户。首版只做单市场（默认 IBM），每侧 $400。详细规则以 design.md 第三版为准：
  - **报价**：post-only GTC 双边单，以第三方盘口（扣除我方挂单）中点为中心价，用独立慢锚防止自我引用，离中心 12±4bps。
  - **订单状态机**：固定 clientOrderId、UNKNOWN 消歧、撤单确认后才挂新单、同步屏障、持仓水位。
  - **风险控制**：下单前最坏敞口与保证金检查；软上限保留双边，硬上限用 IOC 减仓并有重试预算；本轮窗口累计亏损熔断（持久化保存）。
  - **安全机制**：先写熔断锁再撤单；死人开关收到 ACK 才下单，续期与存活绑定，不健康时封锁所有续期路径。
  - **限流与错误**：带优先级的限速队列（1 次/秒）和错误码分类。
  - **判据与窗口**：只用第三方盘口计算竞争量；单一窗口；窗口最后 60 分钟降仓。
  - **监控**：live 模式强制 Telegram 告警，并有外部心跳；运行模式分 dry-run、sandbox、live。
- **密钥管理**：只从服务器上的环境变量或权限为 600 的文件读取，永不写入日志或报告。要求 API 密钥只开交易权限、不开提现权限，并设置 IP 白名单。
- **部署**：`deploy/pendle-maker.service`（systemd）、`maker.example.toml`、README 中的实盘章节（含停机与应急步骤）。

## 第二版修订（两方审核后）

- **范围缩小**：只做单市场（默认 IBM），每侧默认 $400（代码上限 $800），账户总敞口上限 $1500，没有任何绕过开关。
- **限流按 1 次/秒设计**（公测默认额度），请求按优先级排队。官方沙盒用于周五上午验收。
- **新增**：
  - 订单状态机（固定 clientOrderId、UNKNOWN 状态消歧、撤单确认后才挂替换单）
  - 同步屏障
  - 下单前的最坏敞口与保证金检查
  - 错误码分类
  - 扣除我方挂单后的参考中心价（第三方盘口中点），并用独立慢锚防止自我引用；标记价格只作辅助守卫
  - 死人开关的续期与存活绑定
  - 软上限保留双边、硬上限 IOC 的重试预算
  - 窗口末尾降仓
  - 强制 Telegram 告警与外部心跳
  - 单实例锁
- **砍掉**：币安守卫（改为只读参考）、多窗口、回测重构、估算奖励份额。

## 明确不做

跨所对冲（Lighter 等）、提现或转账、自动入金、多账户、杠杆自动调整（使用账户现有设置并在启动时校验）、高频套利、自动领取奖励。

## 交付与验收

- 周四：提案经两方审核后，由 Codex 开发，用模拟交易所测试。
- 周五上午：沙盒验收实测清单。周五下午：每侧 $50 实盘至少 2 小时，满足量化验收条件；任何一项不满足就延期。
- 周六 09:00：自动判据通过后，正式开跑。

## Impact

- Affected specs: 新增 `live-maker-bot`。
- Affected code: 新增 `pendle/ondo_api.py`（签名、REST、私有 WS、限速队列）、`pendle/maker_orders.py`（订单状态机）、`pendle/maker_risk.py`（敞口、守卫、熔断、死人开关看门狗）、`pendle/maker.py`（策略与主循环）、`pendle/alerts.py`；回测代码不变；`cli.py` 新增 `maker` 与 `maker-cancel-all`；新增 `deploy/` 与测试。
- **风险**：会操作真实资金。默认 dry-run；切换到 live 需要显式参数加配置确认，并且受硬上限限制。
