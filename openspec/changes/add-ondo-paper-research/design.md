# Ondo／Lighter 研究工具设计

日期：2026-11-03。范围：公开行情录制＋单标的模拟，不涉及真实交易。

## 架构与数据流

`config → market → recorder → SQLite → paper → JSON 报告`

- `config.py`：TOML 和强校验；非法值、非有限数字、未知配置键明确失败。
- `market.py`：公开 GET、接口响应校验、Decimal 规范化盘口、元数据解析。使用明确 User-Agent；HTTP 超时和限流不无限重试；429 尊重 Retry-After（等待上限 60 秒）后由下一采样周期重试，不使用旧盘口冒充新数据。
- `storage.py`：SQLite 会话、样本、错误；样本顺序以接收时间及递增 ID 为准，保存每个来源的独立时间。保存成功即提交，Ctrl-C 不丢已提交样本。会话固定 schema_version、engine_version、symbol、两平台映射、合约元数据；回放只允许策略／费用／风险参数覆盖，身份或不支持版本不匹配、样本时间倒退时拒绝。
- `recorder.py`：两来源并行采样，有限超时；失败样本带错误且不进入有效模拟。支持有限时长，默认不会后台常驻。
- `paper.py`：只消费已观察到的样本，订单和对冲是内存中的模拟状态，不包含任何交易传输接口。
- `__main__.py`／`cli.py`：`record`、`replay`、`demo` 三条命令；JSON 输出机器键名使用英文，说明及错误中文。

## 已验证的公开接口

2026-11-03 北京时间，以匿名 GET 实测 200：

- Ondo `https://api.ondoperps.xyz/v1/perps/depth?market=INTC-USD.P&depth=20`，响应 `success/result/market/time/bids/asks`。
- Ondo `https://api.ondoperps.xyz/v1/perps/contracts`，含标的、手续费、资金费字段；文档认证说明不能替代实际可用性检测。
- Lighter `https://mainnet.zklighter.elliot.ai/api/v1/orderBooks`，按 `symbol=INTC`、`market_type=perp`、`status=active` 唯一解析 `market_id`，并记录数量精度与 multiplier，非一倍线性合约拒绝模拟。
- Lighter `.../api/v1/orderBookOrders?market_id=<动态查询>&limit=50`，按 `price` 和 `remaining_base_amount` 聚合同价订单。该响应没有可靠盘口源时间，必须标注接收时间口径，不得声称已证明报价新鲜。

## 最小模拟规则

1. 报价以当前 Ondo 中间价为锚，按配置距离生成双边限价；向外取整到配置价格步长，数量向下取整。真实合约精度在首版作为显式假设展示。不能跨越当前买卖价，不在创建同一样本成交。
2. 仅在后续有效样本严格穿越旧报价时记为“假设成交”：买单须当前卖价低于买价，卖单反之；触价不算成交。成交价固定为旧挂单限价，不能按穿越后的更好价格记账。最多按可见穿越价位数量模拟部分成交，不虚构无限流动性，不把盘口变化当作真实成交记录。
3. 更新报价需先请求模拟撤单；等待 `cancel_latency_ms`，旧单在等待期间仍可能成交，撤单完成才放新单。
4. 每次模拟成交累计待对冲敞口；直到 `hedge_latency_ms` 后的首个有效样本，且 Lighter 自身接收时间必须不早于对冲到期时刻，才按 Lighter 对手盘口逐档计算实际可用对冲数量与均价。考虑数量步长、配置费用及额外不利滑点。深度不足／超出滑点预算则保留残留敞口并停止新报价；后续有效数据可继续降低敞口。
5. 行情缺失／过期、两边接收时间差过大、跨平台价差过大、短时价格跳变、库存上限、净敞口上限或亏损预算触发后，请求撤单并停止新增报价。严重风险与数据中断保守锁存至回放结束；不得因一次恢复正常自动继续增加风险。持仓不因撤单消失。
6. 两来源分别维护深度消费预算，同一样本的多笔成交和对冲共享扣减；接收时间改变不能刷新额度。连续不变的盘口不会补充可用数量，逐价位仅观察到数量增加时补充增量，数量减少时下调剩余额度；价位消失后重现被视为新增可见流动性，明确是模型假设。
7. 对冲使用可见数据，不使用未来样本；样本间发生过什么无法重建，报告展示采样间隔和最大数据缺口。大于时效阈值的时间段不计有效报价时间；回放末尾订单／对冲不自动假设完成。

## 损益与报告

两平台分别记录现金流、持仓和手续费；结束时按各平台最后有效买卖一档价格给出持仓账面估值；该估值不检查完整退出深度，也未扣除未来平仓费用，不称为完整清算价值或已实现收益。价格来源时间和估值是否陈旧必须展示，不声称真实平仓。无有效终值时净损益为未知，不能用零补齐。分别显示未对冲数量、挂单潜在敞口、未执行对冲、最大净敞口与风险事件。

首版不推断官方奖励。用户可提供一个“假设总奖励”用于情景分析，默认缺省；报告同时给出奖励前损益、明确输入的奖励情景及覆盖模拟成本所需补贴。不计算年化。资金费以显式双边每小时费率假设按分段持仓积分计提；实际结算时点未仿真，报告始终说明该限制。

报告必须标明：这是离散盘口驱动的假设成交模型；缺少真实排队、逐笔主动成交和样本间行情，不能证明实盘盈利，也不模拟保证金和强平。

## 测试与交付

使用 unittest 和临时 SQLite，固定时间与内存 HTTP 响应验证接入。重点覆盖字段异常、重复价位、空／交叉盘口、市场映射、无前视、触价不成交、部分成交、撤单期间成交、延迟对冲、深度不足、过期／缺失行情、最坏挂单库存、费用与终值、未平仓风险。用本地 HTTP 测试服务验证 GET 和限流错误路径；再做官方 API 短时烟测。

只建一个 Python 包、tests、示例配置、README 和 OpenSpec 文件。无需 Docker、数据库服务、前端或交易 SDK。

## 审核修订契约

由两个独立 agent 提出并采纳：重复流动性预算、会话身份／版本绑定、逐来源事件时间门控、旧限价成交与BBO账面终值。配置与元数据按原始会话固定；额外费用、资金费和奖励均为显式假设，不从当前接口数据回填过去。采样重试不改变历史失败样本。两平台 USD/USDC 按1:1记账，未模拟稳定币脱锚。


## 审核最终补充

- 事件顺序：每组样本内部按各来源接收时间排序，分别处理 Ondo 撮合／撤单、Lighter 到期对冲；两来源都可见后才做新报价决策。相同时间固定 Ondo 撮合先于 Lighter 对冲，新报价最后创建；撤单生效同刻保守地先处理可能成交再确认撤单。
- 资金费：正费率表示多头支付、空头收取；每个事件前按变化前持仓计提上一时段，分别使用两平台模拟持仓及名义额。没有填入的实际资金费不能称为已计实际成本。
- 若活动挂单期间出现数据缺口／失败／过期，设置 execution_history_incomplete；不能证明缺口内没有成交。报告同时给出采样间隔、最大缺口、实际模拟成交至对冲的等待时间，而非把配置延迟当作执行精度。
- 库存按 Ondo、Lighter 分别评估；净敞口接近零不豁免单个平台的库存限制。同侧挂单全部成交的潜在库存必须计入。
